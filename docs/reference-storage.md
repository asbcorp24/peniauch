# Хранение эталонов VocalLab (план реализации)

## Цель

Не хранить постоянные WAV. После получения эталона извлекать измерения из исходного PCM **до сжатия**, создавать аудиокопию для прослушивания и удалять временный WAV **только после успешной проверки обоих результатов**.

## Форматы

- `reference.mp3` — моно MP3 128 кбит/с для прослушивания на HW-261.
- `reference.json` — временная шкала высоты F0, уверенности, RMS, voiced/unvoiced, метаданные анализа и версии алгоритма.
- `reference.wav.tmp` — только временный исходник, не долговременное хранилище.

MP3 кодируется **в браузере**, с локально размещённым WASM/JS энкодером (без CDN), поскольку VS1053B декодирует MP3, но не предоставляет штатный MP3-энкодер. Выбор библиотеки и лицензии — отдельная задача. При записи самим VS1053B формат входного потока может отличаться (например, Ogg/ADPCM), и тогда сначала потребуется декодирование для анализа.

## Порядок транзакции

1. Принять исходное аудио (в идеале — анализировать в браузере до передачи).
2. Вычислить F0, RMS и прочие признаки на несжатом PCM.
3. Сформировать MP3 и JSON, проверить корректность, длительность и синхронизацию.
4. Загрузить на microSD как временные `.part` файлы.
5. Проверить размер, структуру JSON, заголовки MP3 и контрольные суммы.
6. Атомарно по возможности опубликовать новый эталон через manifest, сохраняя предыдущую версию до успешного переключения.
7. Только после этого удалить исходный WAV и старую версию.

Не удалять WAV при ошибках анализа, кодирования, записи на SD или при отключении питания.

## Статус

**Это проектное решение, а не готовая функция прошивки.** Сейчас `src/main.cpp` сохраняет `/reference.wav` и строит только RMS в браузере. В нём ещё нет MP3-кодировщика, извлечения F0, транзакционного сохранения и очистки WAV. Не показывать пользователю, что эти функции уже работают.

## Оценка объёма

Моно WAV 16 кГц 16 бит: ~1.92 МБ/мин.
MP3 128 кбит/с: ~0.96 МБ/мин.
MP3 64 кбит/с: ~0.48 МБ/мин.
JSON зависит от частоты измерений и формата, обычно десятки/сотни КБ.
