# VocalLab — хранение записей через Ogg Vorbis

## Выбранная архитектура

HW-261 (VS1053B) записывает микрофон в Ogg Vorbis с помощью encoder-плагина, если он доступен и совместим с данной ревизией. ESP32-S3 считывает поток по SPI и сохраняет на microSD. Веб-клиент получает Ogg, декодирует в PCM, рассчитывает F0, RMS, ритм, вибрато и сохраняет отдельно структурированные характеристики.

Файлы:
- `reference.ogg` — запись преподавателя, сохраняется для прослушивания.
- `reference.json` — временные ряды F0, RMS, voiced, confidence и метаданные.
- `attempt_*.ogg` — запись ученика, опционально.
- `attempt_*.json` — результаты анализа.

**WAV и MP3 не нужны для штатного пути записи.** Импорт внешнего WAV/MP3 можно оставить отдельной функцией позднее.

## Реализация

1. Проверить связь VS1053B и SD, корректность микрофонного тракта.
2. Добавить бинарный encoder-плагин VS1053B в firmware (с проверкой источника и лицензии), загрузить его через SCI.
3. Реализовать старт/стоп записи, чтение кодированных слов по SPI и запись Ogg на SD. Обрабатывать DREQ, ошибки, таймауты и завершение потока.
4. Добавить API записи и выдачи файлов в веб-интерфейс.
5. В браузере декодировать Ogg Vorbis (проверить нативную поддержку; при необходимости использовать локальный WASM-декодер без CDN).
6. Анализировать PCM после декодирования, сохранить JSON, проверить синхронизацию временных меток.
7. Публиковать новый эталон только после успешной записи и проверки обоих файлов.

## Ограничения и проверка

- VS1053B поддерживает Ogg Vorbis encoding при загрузке специального плагина; это не означает, что он автоматически доступен в прошивке.
- Не обещать одновременно запись и MP3-декодирование на одном кодеке без проверки режима.
- Для точной оценки вокала измерить влияние кодирования на F0, RMS и вибрато, сравнив с несжатым сигналом.
- Не удалять единственный рабочий эталон при неудачной записи.
- В рабочей ветке реализован **экспериментальный** драйвер записи Ogg: загрузка P&H encoder-образа `/v44k1q05.img` с microSD, управление записью через `/api/record/start` и `/api/record/stop` (POST), сохранение `/recording.part` с последующим переименованием в `/recording.ogg`, скачивание через `/api/record/file`. После остановки проверяется только начальная сигнатура `OggS`; это **не полная проверка корректности Ogg/Vorbis**. Драйвер не проверен на реальной плате и не собран в CI. Без совместимого encoder-образа запись не запустится. Источник образа: VLSI Solution VS1053 Ogg Vorbis Encoder / пример Adafruit record_ogg; проверьте лицензию перед распространением. В веб-интерфейсе также остаются загрузка WAV и готового Ogg.

## Анализ вокала в браузере

Маршрут `GET /analysis` отдаёт встроенную в прошивку gzip-страницу `web/analysis.html` (генерируется `scripts/embed_analysis.py` при сборке PlatformIO). Можно выбрать локальный аудиофайл или получить `/api/record/file` либо `/api/reference/ogg`.

После декодирования через Web Audio API браузер сводит каналы в моно, рассчитывает RMS/dBFS и приближённую F0 по нормализованной разностной функции (YIN-подобный прототип, 45 мс окно, ~20 мс шаг, диапазон ~75–1000 Гц). Результаты выводятся на двух графиках и экспортируются как JSON с `time`, `hz`, `note`, `confidence`, `rmsDb`. Анализ не загружается автоматически обратно на microSD; JSON скачивается на компьютер. Автоматическая оценка ученика и сравнение с преподавателем ещё не реализованы.

**Ограничения:** декодирование Ogg зависит от поддержки браузера, оценка F0 может ошибаться на шуме, вибрато, хоре и при слабом сигнале; скорость анализа зависит от мощности клиентского устройства. Сборка и тест на плате ещё не выполнены.

## DSP непосредственно на ESP32-S3

Добавлен прототип `include/vocal_dsp.h` для **моно PCM16 WAV 8–48 кГц**: оконный RMS/dBFS, нормализованная автокорреляция для F0 в диапазоне примерно 75–1000 Гц, запись кадров в JSON на microSD. Запуск: `POST /api/analyze/wav` после загрузки `reference.wav`; результат: `GET /api/analyze/result` (`/reference-analysis.json`). Вычисления выполняет ESP32 без браузера. Это первичный алгоритм без оценки точности, сравнения с эталоном и подавления октавных ошибок.

**Важно:** штатная аппаратная запись VS1053 в Ogg пока не подключена к этому DSP: Ogg необходимо декодировать в PCM на ESP32 или получать PCM напрямую. Пока WAV — вход для испытания вычислительного ядра. Запрос анализа выполняется синхронно и может задерживать ответы веб-сервера на длинных файлах. Не подтверждено сборкой или тестом на плате.

## Выбранная архитектура: PCM для анализа, Ogg для воспроизведения

Для записи с микрофона выбран официальный VLSI PCM Recorder plugin **vs1053b_24k_l.img** (24 кГц, 16 бит, моно, левый вход MIC при SM_LINE1=0). Поместить файл из официального пакета `vs1053-vs1063-pcm-recorder-131.zip` в корень SD. Прошивка загружает P&H IMG, запускает PCM захват через SCI_HDAT1/SCI_HDAT0, пишет `/recording.part`, исправляет размеры RIFF/WAV после остановки и сохраняет `/recording.wav`. Маршруты: `POST /api/record/start`, `POST /api/record/stop`, `GET /api/record/file`.

Для анализа **на ESP32**: `POST /api/analyze/wav?source=recording` создаёт `/recording-analysis.json`; `GET /api/analyze/result?source=recording` скачивает JSON. Анализ пока запускается после завершения записи, а не потоково во время записи. Это следующий этап оптимизации.

Ogg оставлен для **воспроизведения**: `POST /api/play/ogg` проигрывает `/reference.ogg` через VS1053B. Ogg-энкодер для захвата больше не используется. Конвертации WAV → Ogg в прошивке нет; готовый Ogg можно загрузить через веб-интерфейс. Одновременно PCM-запись и воспроизведение на одном VS1053B не предусмотрены.

**Ограничения:** прошивка не собрана и не испытана на HW-261; нужно проверить SPI, физическое подключение MIC, формат плагина, работу SCI и корректность WAV. Загрузка PCM и запись на SD требуют обслуживания FIFO без длительных блокировок. Источник: VLSI Solution VS1053B/VS1063A WAV PCM Recorder rev 1.31.
